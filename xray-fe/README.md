# X-Ray — Мини-приложение для платформы MAX (Frontend)

**Клиентская часть сервиса AI Business X-Ray: адаптивное кроссплатформенное мини-приложение в дизайн-системе мессенджера MAX**

> **Трек хакатона:** «Эффективный бизнес» (Минобрнауки России & Платформа MAX)  
> **Стек:** React 19, TypeScript, Vite, `@maxhub/max-ui`, `MAX Bridge`, React Router 8, Marked  
> **Среда выполнения:** Мобильная и веб-версии мессенджера MAX, современные веб-браузеры  
> **Дизайн-система:** Официальная библиотека компонентов `@maxhub/max-ui` (v0.5.0)

---

## 1. Назначение и соответствие требованиям хакатона

Фронтенд реализован в строгом соответствии с требованиями регламента трека «Эффективный бизнес»:

1. **Единая среда взаимодействия в MAX:** Мини-приложение не изолировано, а бесшовно подключено к официальному чат-боту платформы [`@se14421867_bot`](https://max.ru/se14421867_bot?startapp). Пользователь запускает его нажатием инлайн-кнопки `open_app` во встроенном нативном WebView мессенджера.
2. **Кроссплатформенная доступность:** Интерфейс гарантированно корректно работает как в мобильных клиентах MAX (iOS, Android), так и в десктопной и веб-версиях мессенджера.
3. **Платформенный бонус:**
   - Полноценное использование библиотеки **`@maxhub/max-ui`**: интерфейс органично выглядит как часть экосистемы MAX, поддерживает нативные стили, цветовые схемы, типографику и элементы управления.
   - Использование **`MAX Bridge`**: приложение считывает контекст платформы запуска, адаптирует отступы под системные безопасные зоны (Safe Areas) и передает заголовок `X-Max-Init-Data` для безопасной сквозной авторизации.
   - **Интерактивный AI-консультант внутри мессенджера:** пользователь может вести живой диалог с нейросетью с потоковой печатью символов (SSE) и наглядным отображением вызовов инструментов базы данных (**Tool Calling**).

## 2. Архитектура экранов и пользовательский сценарий

```
┌─────────────────┐      ┌──────────────────┐      ┌─────────────────┐
│    Home.tsx     ├─────►│   Mapping.tsx    ├─────►│  Processing.tsx │
│ (Шаблон / Файл) │      │ (AI-нормализатор)│      │ (Анимация скана)│
└─────────────────┘      └──────────────────┘      └───────┬─────────┘
                                                           │
       ┌───────────────────────────────────────────────────┘
       ▼
┌─────────────────┐      ┌─────────────────┐      ┌─────────────────┐
│  Diagnosis.tsx  ├─────►│ ChatScreen.tsx  │      │CompareScreen.tsx│
│ (Рентген воронки)│     │ (SSE + Tools)   │      │(ДО vs ПОСЛЕ)    │
└────────┬────────┘      └─────────────────┘      └─────────────────┘
         │
         ▼
┌─────────────────┐
│ Экспорт отчетов │
│  (PDF / Excel)  │
└─────────────────┘
```

1. **`Home.tsx` (Главный экран):**
   - Выпадающее меню **«Шаблон ▼»** для тестирования в 1 клик (*Стандартный E-commerce*, *1С / МойСклад*, *Wildberries / Ozon*, *Сленговая CRM*).
   - Зона Drag & Drop для загрузки файлов пользователя (`.csv`, `.xlsx`, `.xls`).
   - Кнопка авторизации и импорта воронок из **amoCRM** по OAuth 2.0.
   - Секция **«История сканов»**: список ранее выполненных расчетов из БД с оценкой здоровья воронки и датой.
2. **`Mapping.tsx` (Подтверждение и AI-маппинг колонок):**
   - Наглядная валидация соответствия колонок входного файла канонической структуре.
   - Индикаторы готовности каждой из 8 бизнес-метрик в реальном времени.
   - Автоматическая семантическая подстановка через AI-нормализатор для нестандартных названий.
3. **`Processing.tsx` (Экран расчета):**
   - Анимированный процесс диагностического «рентгена» воронки с опросом статуса готовности снимка через API.
4. **`Diagnosis.tsx` (Итоговое медицинское заключение по бизнесу):**
   - Общий вердикт и точная сумма финансовых потерь в рублях (`money_impact`).
   - Интерактивные карточки уязвимостей с сортировкой по уровню угрозы (`CRITICAL`, `WATCH`, `OK`).
   - Кнопки моментальной выгрузки **«📄 Скачать PDF»** (презентация) и **«📊 Скачать Excel»** (реестр сделок).
   - Кнопка перехода в интерактивный AI-чат.
5. **`ChatScreen.tsx` (Интерактивный AI-консультант):**
   - Потоковая трансляция ответа модели (Server-Sent Events) с эффектом мгновенной печати.
   - Рендеринг структурированного Markdown с таблицами и списками.
   - **Интерактивные бейджи Tool Calling (`ToolCallBadge.tsx`)**: раскрывающиеся карточки с параметрами SQL-запросов к базе данных, подтверждающие фактологическую достоверность ответов AI.
6. **`CompareScreen.tsx` (Сравнение периодов ДО и ПОСЛЕ):**
   - Сопоставление двух срезов продаж (например, до оптимизации и после) с расчетом динамики метрик и суммы спасенной выручки.
7. **`MetricDetail.tsx` (Детализация уязвимости):**
   - Просмотр формул расчета, пороговых значений и конкретного списка сделок, попавших в зону риска.

## 3. Локальный запуск и разработка

### Шаг 1: Установка зависимостей
```bash
cd xray-fe
npm install
```

### Шаг 2: Конфигурация переменных окружения (`.env.local`)
```env
# URL бэкенда (по умолчанию локальный Django сервер)
VITE_API_BASE_URL=http://localhost:8000

# Режим автономных мок-фикстур (false = работа с реальным бэкендом)
VITE_USE_FIXTURES=false
```

### Шаг 3: Запуск сервера разработки (Vite Dev Server)
```bash
npm run dev
```

Приложение будет доступно по адресу [http://localhost:5173](http://localhost:5173).  
Все запросы `/api/*` автоматически проксируются через Vite на бэкенд `http://127.0.0.1:8000`.

---

## 4. Сборка и Docker-конфигурация

### Сборка статических файлов (Production Build):
```bash
npm run build
```
Результат сборки компилируется в директорию `dist/` с проверкой типов TypeScript.

### Запуск через Docker:
В составе `docker-compose.yml` фронтенд компилируется внутри контейнера `xray-fe/Dockerfile` и раздается легковесным веб-сервером **Nginx Alpine**:
- Сетевые порты: `80` (основной) и `5173` (alias для совместимости).
- Сжатие gzip и кэширование статических ассетов включены по умолчанию.
