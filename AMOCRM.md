# Интеграция X-Ray с amoCRM

Документ описывает, как мини-приложение само забирает сделки из amoCRM, какие правки внесены в код и что сделано в учебном кабинете.

## Что умеет интеграция

Мини-приложение больше не зависит только от CSV. Пользователь вводит поддомен кабинета и долгосрочный токен. Сервер проверяет токен, читает сделки через API amoCRM v4, приводит их к канону X-Ray (клиент, сумма, статус, дата создания) и сразу считает снимок. Пока Django запущен, кабинет перечитывается примерно раз в пять минут. Кнопка «Обновить» делает то же сразу.

Вебхук и публичный HTTPS для локальной работы не нужны: запросы идут с компьютера в amoCRM.

Адрес интерфейса: `http://localhost:5173/`  
Адрес API: `http://localhost:8000/` (это не страница приложения)

Запуск двух окон: двойной щелчок по `D:\Unity\Projects\xray-business\start-xray.bat`. Окна не закрывать.

## Как подключить amoCRM из мини-приложения

1. Откройте `http://localhost:5173/`.
2. На главной нажмите **Подключить amoCRM**.
3. В первое поле впишите поддомен: `liaisanbedr` (не страницу `/amo-market/`).
4. Во второе поле вставьте долгосрочный токен интеграции.
5. Нажмите **Забрать сделки из amoCRM**.

Если в сделках есть бюджет больше нуля, откроется диагноз. Если сумм нет, кабинет всё равно сохраняется, на экране появляется подсказка заполнить поле «Бюджет», затем **Обновить**.

Токен в интерфейс обратно не показывается. После хакатона его лучше отозвать в amoМаркете и выпустить новый, потому что он уже передавался в чате.

## Изменения в бэкенде (`xray-be`)

Новые файлы:

| Файл | Назначение |
|------|------------|
| `engine/amo_client.py` | Хост кабинета, запросы к `/api/v4/account`, воронкам и сделкам, перевод в строки таблицы |
| `engine/amo_sync.py` | Сохранение токена, сбор снимка тем же движком, что и CSV |
| `engine/amo_views.py` | HTTP: статус, подключение, ручное обновление; фоновый опрос каждые 5 минут |
| `engine/migrations/0008_amoconnection.py` | Таблица подключений |
| `engine/migrations/0009_deal_amount_wider.py` | Сумма сделки до 20 знаков |

Правки существующих файлов:

- `engine/models.py` — модель `AmoConnection` (пользователь или гостевая сессия, поддомен, подписанный токен, время синхронизации, ошибка, id последнего снимка). У `Deal.amount` `max_digits` увеличен с 14 до 20.
- `xray_be/urls.py` — маршруты `GET /api/amo`, `POST /api/amo/connect`, `POST /api/amo/sync`. На `/` добавлена короткая страница: «это API, интерфейс на :5173».
- `requirements.txt` — пакеты, без которых `manage.py` не стартовал: `djangorestframework`, `PyYAML`, `openpyxl`, `reportlab`.

Как устроен обмен данными:

1. `POST /api/amo/connect` проверяет токен запросом `/api/v4/account`, сохраняет подключение (`django.core.signing`, токен в ответе не отдаётся).
2. Сделки читаются страницами по 250, только с `price > 0`.
3. Строки получают колонки: ID, Клиент, Сумма, Статус, Дата создания, Менеджер.
4. Статусы: системные `142` → «Успешно», `143` → «Отказ», первый этап воронки → «Новая», остальные — имя этапа из amo.
5. Дальше тот же путь, что у файла: `guess_column_mapping` → `normalize_records` → `calculate_metrics_and_findings` → снимок `ready`.
6. Если снимок моложе 2 минут, сделки дописываются в него. Иначе создаётся новый, старые остаются в истории.
7. Отдельный запрос `/api/v4/users/{id}` для имени менеджера **убран**: amoCRM на него часто не отвечала за 25 секунд, и вся загрузка падала. Поле «Менеджер» пока пустое.

Ошибки API в формате `{ "code", "message" }`. Коды: `crm_auth`, `crm_unavailable`, `not_found`.

## Как включить приложение самостоятельно

Файл `start-xray.bat` в корне `xray-business` поднимает два окна:

1. `python manage.py runserver` в `xray-be\xray_be` — порт 8000.
2. `npm.cmd run dev` в `xray-fe` — порт 5173.

Открывать нужно **http://localhost:5173/**. Адрес `https://localhost` без порта — не тот: там нет ни интерфейса, ни API.

## Что рентген считает по amo сейчас

Из amo приходят клиент, сумма, статус и дата создания. Поэтому считаются метрики, которым хватает этих полей (например воронка и концентрация по клиентам).

На экране «не посчитано» остаются показатели, для которых в выгрузке нет колонок:

- скорость первого ответа — нет даты первого контакта;
- зависшие сделки и забытые клиенты — нет даты смены статуса / последней активности;
- утечка скидок — нет скидки или прайса;
- цикл сделки — нет даты закрытия;
- сравнение менеджеров — имя менеджера не запрашивается (из‑за таймаута amo).

Это ограничение текущего импорта, не ошибка входа. Расширение полей amo (даты контакта, скидка, менеджер) — отдельная доработка.
