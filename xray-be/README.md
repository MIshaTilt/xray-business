# X-Ray Backend (Django API & Analytics Engine)

**Серверная часть, детерминированное аналитическое ядро и AI-оркестратор проекта AI Business X-Ray**

> **Трек хакатона:** «Эффективный бизнес» (Минобрнауки России & Платформа MAX)  
> **Стек:** Python 3.11, Django 5.2, Django REST Framework, Gunicorn, PostgreSQL 16 / SQLite, OpenAI-API совместимая LLM  
> **Спецификации:** OpenAPI 3.1 (`openapi.yaml`), План автопроверки `DATA-API.yaml`

---

## 1. Архитектура и принципы работы с данными

В строгом соответствии с рекомендациями трека хакатона (стр. 18 «Работа с официальными данными»), в бэкенде реализовано фундаментальное архитектурное разделение:

```
                  ┌──────────────────────────────────────────────┐
                  │          Табличные данные / amoCRM           │
                  └──────────────────────┬───────────────────────┘
                                         │
                                         ▼
                  ┌──────────────────────────────────────────────┐
                  │    Парсер и AI-нормализатор (parsers.py,     │
                  │        mapping.py, ai_mapper.py)             │
                  └──────────────────────┬───────────────────────┘
                                         │
                                         ▼
                  ┌──────────────────────────────────────────────┐
                  │     Детерминированное математическое ядро    │
                  │                 (analyzer.py)                │
                  │   - Расчет 8 бизнес-метрик по формулам       │
                  │   - Точный расчет ущерба (money_impact) в ₽  │
                  │   - 0% галлюцинаций, строгая воспроизводимость│
                  └──────────────┬────────────────┬──────────────┘
                                 │                │
            ┌────────────────────┘                └────────────────────┐
            ▼                                                          ▼
┌───────────────────────────────┐              ┌───────────────────────────────┐
│     Генерация документов      │              │      Генеративный AI-слой     │
│   (reports.py, reportlab)     │              │  (narrator.py, tools.py, LLM) │
│ - Фирменный PDF-отчет         │              │ - 152-ФЗ PII Anonymizer       │
│ - Двустраничный Excel-аудит   │              │ - Бизнес-резюме аудита        │
└───────────────────────────────┘              │ - SSE-чат с Tool Calling к БД │
                                               └───────────────────────────────┘
```

### 1.1. Математическое ядро без галлюцинаций (`engine/analyzer.py`)
- **Детерминизм расчетов:** AI **не считает финансовые показатели**. Все 8 ключевых метрик (конверсия, средний чек, зависшие сделки, удлинение цикла, раздача скидок, медленный первый контакт, отвал на 1-м шаге, концентрация на ключевых клиентах), а также сумма финансовых потерь (`money_impact`) рассчитываются строго математически на базе алгоритмов Python и Pandas.
- **Оценка критичности:** Пороговые значения определяются на основе отраслевых бенчмарков (`engine/thresholds.yaml`) с градацией статусов: `OK`, `WATCH`, `CRITICAL`.

### 1.2. Генеративный AI-слой и Tool Calling (`engine/narrator.py`, `engine/tools.py`)
- OpenAI-API совместимая LLM используется исключительно для:
  1. Формулирования емких управленческих рекомендаций живым языком предпринимателя;
  2. Интерактивного консультирования в потоковом чате (SSE).
- **Архитектура Tool Calling:** При вопросах пользователя нейросеть вызывает специализированные функции бэкенда (`search_deals`, `get_manager_stats`, `get_top_clients`), которые выполняют прямые SQL-запросы к PostgreSQL и возвращают подтвержденные факты, исключая фантазии модели.

### 1.3. Защита персональных данных (152-ФЗ PII Anonymizer)
- До отправки контекста во внешнюю модель модуль `engine/anonymizer.py` автоматически хеширует и удаляет персональные данные (ФИО клиентов, номера телефонов, email).

## 2. Структура модулей бэкенда

- **`engine/parsers.py`** — Универсальный парсер файлов `.csv`, `.xlsx`, `.xls` с автоопределением кодировок (`utf-8`, `utf-8-sig`, `cp1251`) и разделителей (`;`, `,`, `\t`).
- **`engine/mapping.py`** — Детерминированное распознавание стандартных колонок по словарю синонимов и проверке типов данных.
- **`engine/ai_mapper.py`** — Семантический AI-нормализатор на базе LLM: автоматически сопоставляет нестандартные и сленговые заголовки таблиц (*«Баблос»*, *«Кто тащит»*, *«Клиентос»*).
- **`engine/normalizer.py`** — Приведение строк датасета к канонической структуре модели `Deal`, очистка аномалий и генерация детерминированных SHA-256 идентификаторов.
- **`engine/analyzer.py`** — Ядро расчета 8 бизнес-метрик и финансового ущерба.
- **`engine/narrator.py`** — Синтез текстового заключения и рекомендаций (с детерминированным Fallback-режимом при недоступности LLM).
- **`engine/tools.py`** — Реализация инструментов базы данных для механизма Tool Calling.
- **`engine/reports.py`** — Генератор презентационных PDF-отчетов и детальных Excel-таблиц.
- **`engine/compare.py`** — Алгоритм сравнения двух хронологических срезов воронки (ДО и ПОСЛЕ) с расчетом спасенной выручки.

## 3. Реестр API Эндпоинтов

Сервис предоставляет полнофункциональный REST API, задокументированный в соответствии со стандартами OpenAPI 3.1:

| Метод | Эндпоинт | Роль | Назначение |
| :--- | :--- | :---: | :--- |
| `GET` | `/api/templates` | `guest` | Список встроенных отраслевых шаблонов (E-com, 1C, WB, сленг) |
| `POST` | `/api/templates/<id>/load` | `user` | Мгновенная загрузка выбранного демонстрационного шаблона |
| `POST` | `/api/uploads` | `user` | Загрузка файла выгрузки пользователя (CSV/XLSX/XLS) |
| `PUT` | `/api/uploads/<id>/mapping` | `user` | Подтверждение или редактирование сопоставления колонок |
| `POST` | `/api/snapshots` | `user` | Запуск расчета аналитического снимка и сохранение в БД |
| `GET` | `/api/snapshots` | `user` | История снимков текущего пользователя |
| `GET` | `/api/snapshots/<id>/diagnosis` | `user` | Получение готового заключения, ущерба в рублях и списка угроз |
| `GET` | `/api/snapshots/<id>/metrics/<metric_id>` | `user` | Детализация конкретной метрики с формулами и сделками |
| `GET` | `/api/snapshots/compare` | `user` | Сравнение двух периодов продаж (базовый и целевой снимки) |
| `POST` | `/api/chat/stream/` | `user` | Потоковый SSE-чат с AI-консультантом и Tool Calling |
| `GET` | `/api/snapshots/<id>/chat` | `user` | Получение истории переписки по снимку |
| `DELETE`| `/api/snapshots/<id>/chat` | `user` | Очистка истории переписки |
| `GET` | `/api/snapshots/<id>/export-pdf` | `user` | Скачивание брендированного PDF-отчета |
| `GET` | `/api/snapshots/<id>/export-excel` | `user` | Скачивание расширенного Excel-аудита |
| `GET` | `/api/amo` | `user` | Проверка статуса подключения интеграции amoCRM |
| `GET` | `/api/docs/` | `guest` | Интерактивная документация Swagger UI |
| `GET` | `/openapi.yaml` | `guest` | Машиночитаемая спецификация OpenAPI 3.1 |

## 4. Аутентификация и контекст платформы MAX

Бэкенд поддерживает бесшовную работу с пользователями мессенджера MAX:
1. **Авторизация через MAX (`X-Max-Init-Data`):** Бэкенд считывает параметры сессии пользователя MAX, переданные через `MAX Bridge`, валидирует подпись и автоматически привязывает снимки и историю чатов к профилю пользователя.
2. **Гостевой режим (`X-Guest-Session`):** Для быстрого тестирования без мессенджера генерируется уникальный UUID гостевой сессии.
3. **Панель администратора (`admin`):** Доступ к Django Admin по адресу `/admin/` (логин: `admin`, пароль: `xray2026admin`).

## 5. Локальный запуск и разработка

### Шаг 1: Активация виртуального окружения
```powershell
# Windows PowerShell
cd xray-be
.\venv\Scripts\Activate.ps1

# Linux / macOS
cd xray-be
source venv/bin/activate
```

### Шаг 2: Установка зависимостей
```bash
pip install -r requirements.txt
```

### Шаг 3: Настройка переменных окружения
Создайте файл `xray-be/.env` на основе шаблона (без рабочих секретов):
```env
DEBUG=true
SECRET_KEY=django-insecure-dev-key
ALLOWED_HOSTS=*
CSRF_TRUSTED_ORIGINS=http://localhost:8000,http://127.0.0.1:8000,http://localhost:5173
DB_ENGINE=sqlite
OPENAI_BASE_URL=
OPENAI_API_KEY=
OPENAI_MODEL=
```
*(При локальной разработке при `DB_ENGINE=sqlite` сервер автоматически использует легковесную базу SQLite. Переменные `OPENAI_*` заполняются при необходимости работы с LLM).*

### Шаг 4: Применение миграций и запуск
```powershell
python xray_be/manage.py migrate
python xray_be/manage.py runserver 127.0.0.1:8000
```

## 6. Запуск через Docker

В составе общей Docker-инфраструктуры бэкенд собирается через многоэтапный `xray-be/Dockerfile` и запускается под управлением производственного сервера **Gunicorn**:

```bash
# Из корня репозитория:
docker compose up -d --build backend
```

- Порт сервера: `8000`
- Проверка работоспособности: `curl http://localhost:8000/api/templates`
