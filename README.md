# AI Business X-Ray

**Интеллектуальная система экспресс-диагностики, финансового аудита и поиска точек роста B2B/E-commerce бизнеса для платформы MAX**

---

## 1. Назначение решения

**AI Business X-Ray** — цифровой инструмент финансового рентгена и аудита воронки продаж для малого и микробизнеса (B2B, сфера услуг, E-commerce, оптовая торговля). 

Сервис подключается к воронкам продаж (через загрузку выгрузок CSV/Excel или прямую интеграцию с amoCRM), мгновенно выявляет скрытые финансовые потери (зависшие сделки, удлинение цикла, раздачу чрезмерных скидок, риск потери ключевых клиентов, медленный первый контакт), вычисляет точный ущерб в рублях и предоставляет предпринимателю интерактивного AI-консультанта с доступом к базе сделок через механизм **Tool Calling**.

> **Фундаментальный принцип надежности:**  
> AI **не вычисляет финансовые показатели и не гадает на цифрах**. Расчет всех 8 бизнес-метрик, финансового ущерба (`money_impact`) и критичности угроз выполняется строгим математическим ядром по формулам. Нейросеть (`gemini-3.8-flash-high`) формирует выводы живым деловым языком, отвечает на вопросы предпринимателя в потоковом чате с реальными SQL-запросами к базе данных и помогает сопоставлять нестандартные колонки через **AI-нормализатор**.

## 2. Основной пользовательский сценарий

1. **Вход и выбор источника:** Пользователь открывает мини-приложение в MAX (или веб-версию) и выбирает источник данных:
   - загрузка своего файла (CSV, XLSX, XLS);
   - выбор готового отраслевого шаблона из меню «Шаблон ▼» (E-commerce, 1С, Wildberries/Ozon, сленговая CRM);
   - прямое подключение amoCRM по OAuth 2.0.
2. **AI-нормализация и маппинг:** Система автоматически определяет структуру колонок и стадии сделок. Если заголовки нестандартные, LLM-нормализатор сопоставляет поля на основе семантики и примеров данных.
3. **Экспресс-диагностика (Рентген):** За 1–2 секунды математическое ядро рассчитывает метрики, находит критические уязвимости и отображает карточку диагноза с суммой замороженных средств в рублях.
4. **Интерактивный AI-консультант:** В окне диалога предприниматель задает вопросы (*«Кто из менеджеров чаще всех дает максимальные скидки?»*, *«Покажи зависшие сделки на сумму больше 500 тыс. руб.»*). Ассистент выполняет реальные запросы к базе данных через **Tool Calling** и возвращает конкретные факты и рекомендации.
5. **Сравнение периодов (Динамика):** Пользователь может сравнить два снимка разных месяцев/недель и увидеть динамику ключевых метрик воронки (улучшение/ухудшение, спасенные деньги).
6. **Экспорт отчетов:** Формирование презентационного **PDF-отчета** с оценкой здоровья воронки и двухстраничного детального **Excel-аудита** с реестром проблемных сделок.

* **Frontend:** SPA на React 19, TypeScript, Vite, с библиотекой UI-компонентов `@maxhub/max-ui` в дизайн-системе MAX.
* **Backend:** Python 3.11, Django 5.2, Django REST Framework, Gunicorn.
* **Database:** PostgreSQL 16 (с поддержкой нативных JSONB полей для метрик и индексов). При локальной разработке без Docker поддерживается автоматический fallback на SQLite.
* **API Документация:** `drf-spectacular` с поддержкой интерактивного Swagger UI и ReDoc.
* **Безопасность:** Модуль обезличивания персональных данных (152-ФЗ PII Anonymizer) перед передачей контекста во внешние LLM.

3. **amoCRM (REST API v4 & OAuth 2.0):**
   - Двусторонняя синхронизация воронок, этапов и сделок с автоматическим пересчетом метрик.

## 9. Описание работы с данными

1. **152-ФЗ Комплаенс (PII Anonymizer):**
   Все персональные данные клиентов (ФИО, телефоны, email) автоматически анонимизируются или хешируются до отправки контекста во внешние языковые модели.
2. **Детерминизм и защита от галлюцинаций:**
   Все 8 метрик (конверсия, средний чек, зависание, скидки, скорость реакции, риск потери ключевых клиентов, цикл сделки, отвал воронки) вычисляются на Python строгими математическими алгоритмами. LLM получает на вход только готовые числа.
3. **Хранение в PostgreSQL:**
   - Таблица `engine_snapshot` хранит метаданные аудита и нативные `jsonb` поля с результатами метрик и сравнений.
   - Таблица `engine_deal` хранит отдельные сделки для быстрых аналитических выборок и RAG-запросов.
   - Таблица `engine_chatmessage` хранит историю диалогов предпринимателя с ассистентом.
   - Таблица `engine_maxuser` и `engine_llmusagelog` ведет учет затраченных токенов LLM.

## 11. Пошаговый сценарий проверки

### Сценарий А. Проверка через браузер / MAX MiniApp
1. Откройте [http://localhost](http://localhost) (или боевой сервер [https://xray-business-bot.online](https://xray-business-bot.online)).

6. Убедитесь, что AI вызвал инструмент базы данных (**Tool Calling**) и вывел структурированный ответ с именами и суммами.
7. Нажмите кнопки **«Скачать PDF»** и **«Скачать Excel»** для проверки генерации отчетов.

### Сценарий Б. Проверка API через Swagger UI
1. Откройте [http://localhost/api/docs/](http://localhost/api/docs/) (или [https://xray-business-bot.online/api/docs/](https://xray-business-bot.online/api/docs/)).
2. В интерактивном интерфейсе Swagger UI раскройте метод `POST /api/snapshots`.
3. Нажмите **Try it out** и выполните запрос (тело запроса предзаполнено).
4. Убедитесь, что сервер возвращает статус `200 OK` с идентификатором созданного снимка.
5. Выполните проверку по спецификации [`DATA-API.yaml`](file:///c:/Users/mdsv/Documents/Dev/xray-business/DATA-API.yaml).

## 12. Примеры ожидаемого поведения системы

* **Расчет ущерба:** При обнаружении 12 зависших сделок на общую сумму 1 450 000 руб. система рассчитывает точную сумму замороженных средств и выводит статус `«Критично»`.
* **Smart Mapping:** Если колонка называется `Сумма_сделки_руб`, система автоматически сопоставляет её с каноническим полем `amount`.
* **Tool Calling:** Если в чате спросить *«Найди сделку с клиентом ООО Вектор»*, нейросеть формирует аргумент `{"query": "Вектор"}` для инструмента `search_deals`, находит запись в базе и цитирует её параметры.

* **Максимальный размер файла:** 50 МБ для разовой загрузки через веб-интерфейс.
