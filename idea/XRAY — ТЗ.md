## 1. Общие сведения

### 1.1. Название
**AI Business X-Ray** — интеллектуальный сервис бизнес-диагностики, финансового рентгена и AI-консалтинга для малого и микробизнеса.

### 1.2. Назначение
Сервис принимает выгрузку продаж и сделок предпринимателя (CSV или Excel), автоматически приводит её к канонической схеме данных, рассчитывает 7 ключевых аналитических бизнес-метрик детерминированным ядром, оценивает финансовый ущерб в рублях (`money_impact`) и предоставляет:
1. Понятный диагноз финансового здоровья бизнеса простым языком.
2. Пошаговые приоритетные рекомендации на ближайшую неделю.
3. Интерактивного AI-консультанта в формате диалога с доступом к базе данных через Tool Calling (SQL и графики).
4. Профессиональные PDF и Excel отчеты для собственника, РОПа или инвесторов.

### 1.3. Фундаментальный принцип надежности
> **AI не вычисляет финансовые показатели и не гадает на цифрах.**  
> Расчёт всех 7 бизнес-метрик, финансового ущерба (`money_impact`), пороговых отклонений и критичности угроз выполняется **строгим детерминированным ядром по неизменным формулам**.  
> Нейросеть (`gemini-3.8-flash-high`) решает только задачи, требующие семантического понимания:
> - Формулирует выводы живым деловым языком (Narrator);
> - Сопоставляет нестандартные сленговые названия колонок при импорте (AI-Mapper);
> - Консультирует предпринимателя в чате, обращаясь к базе данных сделок через **Tool Calling (SQL SELECT)**, исключая галлюцинации и выдуманные факты.

### 1.4. Цель и ключевой сценарий
Обеспечить мгновенное получение аудита и рекомендаций без привлечения сторонних аналитиков:
1. **Вход:** открытие мини-приложения в MAX (или браузере).
2. **Загрузка данных:** загрузка файла CSV/XLSX, выбор готового шаблона или запуск демо.
3. **Сопоставление (Smart Mapping):** автоматическое определение колонок алгоритмами и LLM с возможностью ручной корректировки.
4. **Рентген и Диагноз:** расчет 7 метрик, выявление топ-3 критических утечек денег, расчет общего балла здоровья воронки (0–100).
5. **AI-Консультант:** возможность задать любой вопрос по отчёту («Кто из менеджеров косячит?», «Построй график выручки») с получением точных цифр и интерактивных визуализаций.
6. **Экспорт:** скачивание фирменного PDF или Excel-аудита, либо копирование резюме в буфер обмена.

### 1.5. Границы продукта

#### Входит в систему:
- Поддержка архетипов «Сделочный B2B / услуги», «E-commerce / розница», «Маркетплейсы»;
- Чтение CSV (UTF-8, UTF-8-BOM, CP1251, автоопределение разделителей `;`, `,`, `\t`) и Excel (`.xlsx`, `.xls`);
- Аналитическое ядро из 7 детерминированных метрик с грациозной деградацией при отсутствии необязательных колонок;
- AI-нормализатор колонок и этапов воронки (Smart Heuristics + LLM Fallback);
- Автоматическая генерация вычисляемых колонок (скидки, базовая цена);
- Мини-приложение с экранами: Home, Templates, Mapping, StatusMap, Processing, Diagnosis, Chat, MetricDetail, MissingData, Scans;
- Интерактивный SSE-чат с AI-консультантом с поддержкой Tool Calling (SQL-запросы к сделкам и построение графиков `ChartCard`);
- Генерация PDF-отчета (ReportLab) и двухстраничного Excel-аудита (OpenPyXL);
- Библиотека предустановленных демонстрационных датасетов;
- История сканов с нумерацией, свайпом для удаления и изоляцией сессий;
- Тонкий лаунчер: бот MAX, отправляющий приглашение и кнопку `open_app`;
- Логирование и подсчет расхода токенов LLM (`prompt_tokens`, `completion_tokens`).

#### Не входит в систему:
- Продуктовый диалог и загрузка файлов внутри чата бота (бот только запускает WebApp);
- Прямая синхронизация с CRM по API (Bitrix24, amoCRM) с авторизацией OAuth (данные передаются файлом);
- Обязательное наличие LLM для базового отчета (при отсутствии LLM формируются шаблонные выводы);
- Многопользовательские роли внутри одного аккаунта (директор / РОП / менеджер с разграничением прав).

### 1.6. Пользователь
Владелец бизнеса, генеральный или коммерческий директор, руководитель отдела продаж компании от 3 до 50 человек. Идентификация выполняется через MAX Bridge (`user.id` из `initData`), либо через изолированную гостевую сессию при веб-доступе.

### 1.7. Роли поверхностей

| Поверхность | Функции | Ограничения |
|-------------|---------|-------------|
| **Бот-лаунчер** | Отправляет краткое приветствие и кнопку «Открыть X-Ray» (`open_app`). Обрабатывает callback платформы. | Не принимает файлы, не выполняет расчётов, не выводит диагнозы. |
| **Мини-приложение (Mini App)** | Полный функционал: загрузка файлов, выбор шаблонов, маппинг, диагноз, интерактивный AI-чат, визуализация графиков, экспорт PDF/Excel, история сканов. | Автономно от сообщений в чате бота. |

## 2. Термины и определения

| Термин | Описание |
|--------|----------|
| **Снимок (Snapshot)** | Сохраненный результат одного аналитического аудита таблицы сделок, включающий метрики, выводы, балл здоровья и изолированные сделки. |
| **Каноническая модель (`Deal`)** | Внутренняя нормализованная структура данных сделки/заказа с фиксированными типами полей. |
| **Smart Mapping** | Двухэтапный процесс сопоставления колонок файла: эвристический поиск по словарям синонимов и типам данных + AI-fallback через LLM для нестандартных названий. |
| **Деградация данных (Graceful Degradation)** | Способность сервиса рассчитать доступные метрики при отсутствии части колонок без падения с ошибкой. |
| **Вердикт метрики** | Категория состояния показателя: `ok` (в норме), `watch` (требует внимания), `critical` (критическая утечка денег), `skipped` (недостаточно данных). |
| **Money Impact** | Оценка прямого финансового ущерба бизнеса в рублях от конкретной проблемы. |
| **Tool Calling (Function Calling)** | Механизм, при котором LLM формирует структурированный запрос к бэкенду (SQL-запрос или построение графика), бэкенд выполняет операцию над базой данных и возвращает точный результат обратно нейросети. |
| **SSE (Server-Sent Events)** | Протокол однонаправленной потоковой передачи данных с сервера на клиент для мгновенного отображения генерируемого ответа AI. |
| **initData** | Подписанная криптографическим ключом строка контекста запуска мини-приложения в экосистеме MAX. |

## 4. Функциональные требования

### 4.1. Бот-лаунчер
- **FR-1.** На любые входящие события (`bot_started`, команда `/start`, произвольное текстовое сообщение, отправка файла) бот отправляет единое сообщение (до 2 предложений) с inline-кнопкой «Открыть X-Ray» типа `open_app`.
- **FR-2.** Бот не сохраняет файлы пользователей, отправленные в личные сообщения, и не создает сессий анализа через чат.
- **FR-3.** На событие `message_callback` бот выполняет быстрый ответ `POST /answers`, исключая блокировку интерфейса мессенджера.

### 4.2. Мини-приложение (экраны и навигация)
Интерфейс содержит 10 функциональных экранов:
1. **Home:** загрузка файла (Drag & Drop / выбор), выпадающее меню готовых отраслевых шаблонов («Шаблон ▼»), запуск демо-сценария, блок истории сканов.
2. **Templates:** меню выбора демонстрационных наборов данных (E-commerce, 1С/МойСклад, Маркетплейсы, стресс-тест со сленгом).
3. **Mapping:** таблица предпросмотра (до 5 строк), селекты сопоставления «Колонка файла $\to$ Поле канона», плашки автоматически вычисленных полей, индикатор покрытия «N из 7 метрик».
4. **StatusMap:** сопоставление уникальных текстовых статусов из файла пользователя с каноническими этапами воронки продаж (с AI-подсказками).
5. **Processing:** интерактивная завеса анализа (`AnalyzeVeil`) с динамическими статусами выполнения шагов.
6. **Diagnosis:** сводная карточка аудита: балл здоровья воронки (0–100), период, число сделок, выручка, карточки критических находок с суммами ущерба, кнопки «Задать вопрос AI», «Скачать PDF», «Скачать Excel», «Скопировать заключение».
7. **ChatScreen:** интерактивный потоковый чат с AI-консультантом. Отображение плашек вызова инструментов (`ToolCallBadge`), интерактивных графиков (`ChartCard`), подсказок частых вопросов и истории сообщений.
8. **MetricDetail:** детальный разбор конкретной метрики: числовое значение, объяснение порога человеческим языком, таблица сделок-доказательств (`DealTable`) с пагинацией и контактами.
9. **MissingData:** список нераспознанных полей с объяснением, какие аналитические метрики они открывают.
10. **Scans:** экран истории сканирований с нумерацией (#1, #2...), вердиктами, фильтрацией и жестом свайпа для быстрого удаления (`SwipeScan`).

### 4.3. Данные и парсинг
- **FR-4.** Поддерживаются форматы: CSV (кодировки UTF-8, UTF-8-BOM, CP1251, автоопределение разделителей `;`, `,`, `\t`) и Excel (`.xlsx`, `.xls`).
- **FR-5.** Ограничения: максимальный размер файла 25 МБ, до 50 000 строк.
- **FR-6.** Парсер автоматически удаляет пробелы, неразрывные пробелы, символы валют (`₽`, `руб`, `р`, `$`), переводит текстовые числа («1,5 млн», «250 тыс») в строгий `Decimal`.
- **FR-7.** Поддерживаются форматы дат: `DD.MM.YYYY`, `YYYY-MM-DD`, `DD.MM.YY`, даты со временем, Excel serial numbers, текстовые даты на русском языке («14 мая 2024»).

### 4.4. AI-нормализатор колонок (Smart Fallback)
- **FR-8.** На первом этапе маппинг строится по детерминированному словарю синонимов и эвристикам типов данных (§6.6).
- **FR-9.** Если ключевые аналитические поля (`amount`, `status`, `created_at`, `manager`, `deal_id`) не удалось сопоставить эвристикой, система активирует **AI-нормализатор** (`ai_smart_column_mapping`). Нейросеть получает список названий колонок и до 3 примеров строк, после чего определяет назначения сленговых полей (*«Баблос»* $\to$ `amount`, *«Кто тащит»* $\to$ `manager`, *«Время залива»* $\to$ `created_at`).
- **FR-10.** Модуль `derive_computed_columns` автоматически создает недостающие колонки (например, рассчитывает `discount_pct`, если в файле есть только цена и базовая цена, или наоборот).

### 4.5. Нормализация статусов
- **FR-11.** Уникальные текстовые значения колонки статуса маппятся на канонические этапы воронки (`new`, `in_progress`, `proposal`, `negotiation`, `won`, `lost`, `other`).
- **FR-12.** Для нестандартных статусов (*«Пинать в пятницу»*, *«Клиент думает»*, *«Ждем предоплату»*) AI-нормализатор статусов (`ai_smart_status_mapping`) автоматически предлагает релевантный канонический этап с возможностью ручной правки на экране StatusMap.

### 4.6. Аналитическое ядро и расчет 7 метрик
- **FR-13.** Расчет метрик производится строго детерминированным модулем `analyzer.py` без привлечения LLM.
- **FR-14.** Список метрик:
  1. `speed_to_lead` — скорость реакции на лид;
  2. `stagnation` — зависшие сделки без движения с расчетом замороженной суммы в рублях;
  3. `discount_leakage` — утечка маржи через скидки выше допустимого порога;
  4. `sales_cycle` — удлинение цикла сделки;
  5. `key_account_risk` — опасная концентрация выручки на топ-клиентах;
  6. `dormant` — спящие клиенты без повторных покупок;
  7. `funnel_dropoff` — конверсионные провалы на этапах воронки.
- **FR-15.** При отсутствии необходимых колонок метрика получает статус `skipped`, система продолжает работу и формирует диагноз по остальным показателям.

### 4.7. Интерактивный AI-консультант (RAG & Tool Calling)
- **FR-16.** Пользователь может открыть диалог с AI по текущему снимку в любой момент с экрана Diagnosis.
- **FR-17.** Ответ передается потоком через Server-Sent Events (SSE) в реальном времени.
- **FR-18.** Нейросеть имеет доступ к базе данных нормализованных сделок через механизм **Tool Calling**:
  - `execute_sql_query`: выполнение аналитических SQL SELECT-запросов к таблице `deals` текущего снимка (с автоматической фильтрацией `snapshot_id`);
  - `render_chart`: построение интерактивных графиков (`line`, `bar`, `donut`) прямо в ленте сообщений чата;
  - `get_ai_tools_definitions`: динамическая передача доступных пользовательских колонок в схему инструментов.
- **FR-19.** Интерфейс чата отображает плашки вызова инструментов (`ToolCallBadge`) с возможностью раскрыть и просмотреть выполненный SQL-запрос и сырой ответ базы данных.
- **FR-20.** Все сообщения пользователя и ассистента сохраняются в базе данных (`ChatMessage`) с привязкой к снимку.

### 4.8. Экспорт отчетов
- **FR-21. PDF-отчет (`/api/snapshots/{id}/export-pdf`):** формирование брендированного многостраничного PDF-документа:
  - Титульный блок с названием компании/файла и датой;
  - Круговой индикатор общего балла здоровья воронки (0–100);
  - Финансовый блок: общая сумма денег под угрозой (`money_impact`);
  - Подробные карточки выявленных угроз и приоритетный план действий;
  - Реестр проблемных и зависших сделок с номерами и менеджерами.
- **FR-22. Excel-аудит (`/api/snapshots/{id}/export-excel`):** формирование книги Excel с двумя вкладками:
  - Вкладка 1: *«Резюме аудита»* (сводка показателей, статус каждой метрики, сумма потерь, выводы);
  - Вкладка 2: *«Зависшие сделки»* (полный реестр лидов, требующих вмешательства, с суммами, телефонами и ответственными лицами).
- **FR-23. Быстрое копирование:** кнопка «Скопировать заключение» копирует структурированное текстовое резюме диагноза в буфер обмена устройства.

### 4.9. Библиотека отраслевых шаблонов
- **FR-24.** В сервисе доступны предустановленные шаблоны данных:
  - `ecommerce_canonical.csv` — канонический датасет интернет-магазина;
  - `ecommerce_moysklad_1c.csv` — выгрузка номенклатуры и заказов из 1С / МойСклад;
  - `ecommerce_marketplace.csv` — отчет о продажах с маркетплейсов (Wildberries / Ozon);
  - `ecommerce_messy_user_table.csv` — реальная таблица с нестандартными форматами дат и чисел;
  - `custom_messy_slang_crm.csv` — стресс-тест для AI-нормализатора со сленговыми заголовками (*«Баблос»*, *«Кто тащит»*, *«Время залива»*).

### 4.10. История сканов и управление сессиями
- **FR-25.** Все рассчитанные снимки сохраняются в базе данных и выводятся в блоке истории на главной странице и на экране Scans.
- **FR-26.** Каждому снимку присваивается последовательный порядковый номер (`scan_no`: #1, #2...).
- **FR-27.** Карточка скана в истории отображает дату, имя файла, выжимку главных тем диагноза, худший вердикт (`critical` / `watch` / `ok`) и покрытие метрик.
- **FR-28.** Поддерживается жест свайпа влево на мобильных устройствах (`SwipeScan`) для мгновенного удаления снимка.
- **FR-29.** Удаление снимка каскадно удаляет связанные сделки (`Deal`), метрики и историю чата (`ChatMessage`).

## 5. Основные сценарии использования и приёмка

### 5.1. Сценарий А: Быстрый старт через готовый шаблон
1. Пользователь открывает мини-приложение в MAX.
2. Нажимает кнопку **«Шаблон ▼»** и выбирает *«🔥 Стресс-тест для AI-нормализатора»*.
3. Система мгновенно считывает шаблон, AI-нормализатор определяет сленговые заголовки (`Баблос` $\to$ `amount`, `Кто тащит` $\to$ `manager`, `Время залива` $\to$ `created_at`).
4. Открывается экран Mapping с предзаполненными полями.
5. Пользователь нажимает «Просветить» $\to$ через 1–2 секунды открывается Diagnosis.
6. На экране отображается балл здоровья, выявленные утечки денег и приоритетный план.

### 5.2. Сценарий Б: Загрузка реального файла пользователя
1. Пользователь перетаскивает свой файл Excel (`.xlsx`) или CSV в зону загрузки на главной странице.
2. Сервис определяет структуру таблицы, кодировку и типы значений.
3. На экране Mapping пользователь подтверждает распределение колонок.
4. Если есть неизвестные статусы — открывается экран StatusMap, где предлагаются AI-сопоставления.
5. Нажатие «Просветить» формирует снимок, сохраняет нормализованные сделки в БД и открывает диагноз.

### 5.3. Сценарий В: Интерактивный диалог с AI-консультантом
1. На экране Diagnosis пользователь нажимает **«💬 Задать вопрос AI по отчету»**.
2. В чате задает вопрос: *«Кто из менеджеров сливает больше всего сделок?»*.
3. Появляется плашка **`⚙️ Запрос к базе (execute_sql_query)... ▼`**.
4. Нейросеть делает реальный SQL-запрос с группировкой по менеджерам, получает точные цифры и выдает ответ в Markdown с конкретными именами и суммами.
5. Пользователь пишет: *«Построй график динамики выручки по датам»*.
6. AI вызывает инструмент `render_chart(chart_type='line', dimension='date')`.
7. В чате рендерится интерактивный график выручки (`ChartCard`).

### 5.4. Сценарий Г: Экспорт отчетов
1. С экрана Diagnosis пользователь нажимает **«📄 Скачать PDF»** $\to$ скачивается фирменный многостраничный документ с баллом здоровья и реестром сделок.
2. Нажимает **«📊 Скачать Excel»** $\to$ скачивается двухстраничная аналитическая книга (`.xlsx`).
3. Нажимает **«Скопировать заключение»** $\to$ в буфер обмена копируется структурированное резюме диагноза.

### 5.5. Сценарий Д: Работа с историей и свайп-удаление
1. Пользователь переходит на экран **«Сканы»** через нижнее навигационное меню.
2. Видит список своих предыдущих аудитов (#1, #2...).
3. Нажатие на карточку мгновенно открывает сохраненный снимок без повторного пересчета.
4. Свайп карточки влево открывает красную зону удаления с кнопкой корзины.
5. Подтверждение удаляет снимок из базы данных.

## 6. Каноническая схема данных и правила расчёта метрик

### 6.1. Поля канонической модели `Deal`

| Поле | Тип | Обязательность | Описание |
|------|-----|----------------|----------|
| `deal_id` | String(64) | Да | Идентификатор сделки (из файла или детерминированный SHA-256 хеш). |
| `client` | String(255) | Нет | Наименование клиента / контрагента. |
| `contact` | String(255) | Нет | Контактные данные (телефон, email). |
| `manager` | String(255) | Нет | Ответственный менеджер / продавец. |
| `amount` | Decimal(14,2) | Да | Сумма сделки / выручка в рублях (> 0). |
| `list_price` | Decimal(14,2) | Нет | Базовая цена без скидки. |
| `discount_pct`| Decimal(10,2) | Нет | Размер предоставленной скидки в %. |
| `status_raw` | String(255) | Нет | Исходный статус из файла пользователя. |
| `status` | String(32) | Да | Канонический статус (`new`, `in_progress`, `proposal`, `negotiation`, `won`, `lost`, `other`). |
| `created_at` | DateTime | Нет | Дата и время создания сделки / лида. |
| `first_contact_at` | DateTime | Нет | Дата и время первого контакта с клиентом. |
| `status_changed_at` | DateTime | Нет | Дата и время последнего изменения этапа. |
| `last_activity_at` | DateTime | Нет | Дата и время последней активности / звонка. |
| `closed_at` | DateTime | Нет | Дата закрытия / оплаты сделки. |
| `source` | String(255) | Нет | Канал привлечения / источник лида / маркетплейс. |
| `raw_data` | JSON | Нет | Полный набор исходных сырых полей строки для кастомных аналитических SQL-запросов. |

### 6.2. 7 ключевых аналитических метрик

| Метрика (`metric_id`) | Назначение и формула | Требуемые поля | Порог `watch` | Порог `critical` |
|-----------------------|----------------------|----------------|---------------|------------------|
| `speed_to_lead` | Медиана интервала `first_contact_at - created_at`. | `created_at`, `first_contact_at` | > 30 минут | > 120 минут |
| `stagnation` | Открытые сделки, время на текущем этапе > 1.5× медианы цикла успешных сделок (`won`). Эффект = сумма таких сделок. | `status`, `created_at` (или `status_changed_at`) | — | Наличие зависших сделок; сумма замороженных денег формирует `money_impact`. |
| `discount_leakage` | Доля выигранных сделок с `discount_pct > 10%`. Эффект = сумма недополученной маржи `(list_price - amount)`. | `amount`, `discount_pct` (или `list_price`) | Доля > 10% | Доля > 20% сделок со скидкой. |
| `sales_cycle` | Медиана длительности `closed_at - created_at` по выигранным сделкам. Сравнение динамики первой и второй половины периода. | `created_at`, `closed_at`, `status='won'` | Цикл удлиняется (> 0%) | Рост цикла сделки > 30%. |
| `key_account_risk` | Доля выручки, приходящаяся на топ-2 клиентов компании. | `client`, `amount`, `status='won'` | Топ-2 дают > 50% | Топ-2 дают > 65% всей выручки. |
| `dormant` | Клиенты без успешных покупок при отсутствии активности > 45 дней. | `client`, `last_activity_at` (или `created_at`) | Есть такие клиенты | Число $\ge 5$ или сумма их открытых сделок $\ge 500\,000$ ₽. |
| `funnel_dropoff` | Этап воронки с наибольшей потерей потенциальной выручки. | `status`, `amount` | Потеря этапа > 40% | Потеря этапа > 55% суммы входящих сделок. |

### 6.3. Правила расчёта и фильтрации
1. **Часовой пояс:** все даты приводятся к таймзоне `Europe/Moscow`. Дата без времени считается как `00:00:00`.
2. **Валидация сумм:** строки с пустой, нечисловой или неположительной суммой ($\le 0$) отсекаются в список `quality.rejected` с указанием причины (`empty_amount`, `bad_amount`, `non_positive`).
3. **Открытые сделки:** сделки со статусами, отличными от `won` и `lost` (включая `other`).
4. **Недостаточная выборка (`low_sample`):** если по метрикам `speed_to_lead`, `sales_cycle`, `discount_leakage`, `key_account_risk`, `funnel_dropoff` доступно менее 5 наблюдений, метрика помечается флагом `low_sample=true`, её вердикт принудительно устанавливается в `ok`, и она не попадает в топ-3 критических карточек.
5. **Ранжирование топ-находок:** карточки сортируются по убыванию `money_impact` (суммы ущерба в рублях), затем по уровню критичности (`critical` перед `watch`).

### 8.2. Аутентификация и изоляция данных (`auth.py`)
- Запросы к API несут заголовок `X-Max-Init-Data`.
- Бэкенд валидирует криптографическую подпись строки по алгоритму HMAC-SHA256 с использованием секретного ключа бота платформы MAX.
- Поддерживается дебаг-режим (`X-Debug-User` при совпадении `DEBUG_TOKEN`).
- Для пользователей без контекста MAX (веб-версия) генерируется уникальный `X-Guest-Session`. Фоновый поток (`start_background_cleanup_thread`) каждые 5 минут производит автоматическую очистку устаревших гостевых данных, гарантируя безопасность и отсутствие утечек информации между сессиями.

### 8.3. Модели базы данных (`models.py`)
1. **`MaxUser`:** пользователь системы (`max_user_id`, `first_name`, счетчики токенов: `prompt_tokens`, `completion_tokens`, `total_tokens`).
2. **`Upload`:** исходная загрузка файла (`filename`, `columns`, `sample_rows`, `all_rows`, `suggested_mapping`, `mapping`, `status_map`, `source`, `guest_session`).
3. **`Snapshot`:** аналитический снимок (`scan_no`, `filename`, `period_from`, `period_to`, `headline`, `findings`, `coverage`, `totals`, `all_metrics`, `ok_list`, `low_sample`).
4. **`Deal`:** нормализованные сделки снимка (`deal_id`, `client`, `contact`, `manager`, `amount`, `status`, `created_at`, `closed_at`, `source`, `raw_data`).
5. **`ChatMessage`:** сообщения интерактивного чата (`snapshot`, `role`, `content`, `tool_calls`, `created_at`).
6. **`LLMUsageLog`:** аудит обращений к языковой модели (`operation`, `model`, `prompt_tokens`, `completion_tokens`, `total_tokens`, `duration_ms`).

### 8.4. Модуль AI-инструментов (Tool Calling в `tools.py`)
В процессе диалога с пользователем LLM может вызвать зарегистрированные инструменты:
- **`execute_sql_query`:** выполняет `SELECT`-запрос к таблице `engine_deal`. Запрос автоматически обогащается условием `WHERE snapshot_id = '...'`, что исключает доступ к данным чужих сессий. Доступны агрегатные функции (`SUM`, `COUNT`, `AVG`), группировки (`GROUP BY manager`, `GROUP BY client`) и сортировки.
- **`render_chart`:** принимает тип графика (`line`, `bar`, `donut`), параметр группировки (`dimension`), метрику (`amount`, `count`, `avg_check`) и заголовок. Возвращает подготовленный JSON, который клиентский интерфейс преобразует в интерактивный `ChartCard`.
- **Контекстная осведомленность о колонках:** функция `get_ai_tools_definitions(snapshot_id)` динамически передает в описание инструмента реальные названия всех колонок из сырых данных файла пользователя.

## 9. HTTP & SSE API спецификация

Базовый префикс всех бизнес-методов: `/api`.  
Аутентификация: заголовок `X-Max-Init-Data` (или `X-Guest-Session` / `X-Debug-User`).

### 9.0. Формат ошибок
При возникновении ошибки API возвращает структурированный JSON с понятным сообщением на русском языке:

```json
{
  "code": "mapping_incomplete",
  "message": "Необходимо выбрать колонку суммы и статуса или даты"
}
```

### 9.1. Загрузка файла: `POST /api/uploads`
- **Тип запроса:** `multipart/form-data`, поле `file`.
- **Ответ 201 Created:**

```json
{
  "upload_id": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "filename": "deals_2026.xlsx",
  "columns": ["Клиент", "Баблос", "Стадия", "Дата"],
  "sample_rows": [
    {"Клиент": "ООО Альфа", "Баблос": "150 000 ₽", "Стадия": "Оплачено", "Дата": "12.03.2026"}
  ],
  "suggested_mapping": {
    "client": "Клиент",
    "amount": "Баблос",
    "status": "Стадия",
    "created_at": "Дата"
  },
  "coverage": {
    "available": ["stagnation", "funnel_dropoff", "key_account_risk"],
    "skipped": ["speed_to_lead"]
  },
  "auto_computed_columns": []
}
```

### 9.2. Сохранение маппинга: `PUT /api/uploads/{id}/mapping`
- **Тело запроса:**

```json
{
  "mapping": {
    "amount": "Баблос",
    "status": "Стадия",
    "created_at": "Дата",
    "client": "Клиент"
  },
  "status_map": {
    "В работе": "in_progress",
    "Оплачено": "won"
  }
}
```

- **Ответ 200 OK:** обновленный объект `coverage` и предупреждения `warnings`.

### 9.3. Создание снимка: `POST /api/snapshots`
- **Тело запроса:** `{"upload_id": "uuid"}`.
- **Логика:** запускает нормализацию, детерминированный расчет 7 метрик, генерацию нарратива и сохранение объектов `Snapshot` и `Deal` в базу данных.
- **Ответ 200 OK:**

```json
{
  "snapshot_id": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "status": "ready",
  "created": true
}
```

### 9.4. Список сканов: `GET /api/snapshots`
Возвращает историю аудитов пользователя, отсортированную по убыванию даты.

```json
{
  "items": [
    {
      "snapshot_id": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
      "scan_no": 3,
      "status": "ready",
      "created_at": "2026-09-26T21:40:00Z",
      "filename": "deals_2026.xlsx",
      "source": "miniapp",
      "period": {"from": "2026-01-01", "to": "2026-03-31"},
      "headline": "Разморозьте 12 сделок старше 21 дня на 4 200 000 ₽",
      "card_title": "Аудит B2B продаж: Утечки в воронке",
      "topics": ["stagnation", "discount_leakage"],
      "verdict": "critical",
      "coverage_ready": 6,
      "coverage_total": 7
    }
  ],
  "next_cursor": null
}
```

### 9.5. Получение диагноза: `GET /api/snapshots/{id}/diagnosis`
Возвращает полную сводку рентгена, включая балл здоровья, карточки находок, списки метрик в норме (`ok`) и с малой выборкой (`low_sample`).

### 9.6. Детализация метрики: `GET /api/snapshots/{id}/metrics/{metric_id}`
Возвращает рассчитанные параметры метрики и массив подтверждающих сделок (`evidence`).

### 9.7. Потоковый чат с AI-консультантом: `POST /api/chat/stream/`
- **Заголовки:** `Content-Type: application/json`.
- **Тело запроса:**

```json
{
  "snapshot_id": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "messages": [
    {"role": "user", "content": "Кто из менеджеров дал больше всего скидок?"}
  ]
}
```

- **Тип ответа:** `text/event-stream` (Server-Sent Events).
- **События SSE:**
  - Событие вызова инструмента:
    ```text
    data: {"type": "tool_call", "tool_name": "execute_sql_query", "arguments": {"query": "SELECT manager, SUM(amount) FROM deals..."}, "result": "..."}
    ```
  - Событие потокового текста ответа:
    ```text
    data: {"type": "chunk", "text": "По результатам анализа базы сделок..."}
    ```
  - Завершение потока:
    ```text
    data: [DONE]
    ```

### 9.8. История сообщений чата
- `GET /api/snapshots/{id}/chat`: возвращает сохраненную историю переписки по данному снимку.
- `DELETE /api/snapshots/{id}/chat`: очищает историю сообщений.

### 9.9. Экспорт отчетов
- `GET /api/snapshots/{id}/export-pdf`: возвращает бинарный поток `application/pdf` с заголовком скачивания файла `xray_audit_<id>.pdf`.
- `GET /api/snapshots/{id}/export-excel`: возвращает бинарный поток `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` с заголовком скачивания файла `xray_audit_<id>.xlsx`.

### 9.10. Работа с шаблонами
- `GET /api/templates`: возвращает перечень предустановленных отраслевых CSV-файлов.
- `POST /api/templates/{template_id}/load`: загружает выбранный шаблон, выполняет автоматический AI-маппинг и возвращает готовый объект сессии `Upload`.

## 10. Лаунчер и вебхук MAX

- Вебхук лаунчера расположен по адресу: `POST /webhook/max`.
- Проверяет заголовок подписи `X-Max-Bot-Api-Secret` на равенство значению переменной `MAX_WEBHOOK_SECRET`.
- При получении любого входящего события (`bot_started`, `message_created`, `message_callback`) лаунчер отправляет унифицированное приветственное сообщение с inline-кнопкой:

```json
{
  "text": "X-Ray показывает, где в продажах теряются деньги. Откройте приложение и загрузите таблицу сделок.",
  "attachments": [
    {
      "type": "inline_keyboard",
      "payload": {
        "buttons": [
          [
            {
              "type": "open_app",
              "text": "Открыть X-Ray",
              "web_app": "<username бота>"
            }
          ]
        ]
      }
    }
  ]
}
```

## 11. Нефункциональные требования (NFR)

1. **Скорость работы:** расчет аналитического снимка на 5000 строк занимает не более 2 секунд. Формирование первого токена в SSE-чате (с учетом выполнения SQL через Tool Calling) — не более 3.5 секунд.
2. **Отказоустойчивость:** сбой внешнего LLM API не блокирует выдачу основного аналитического диагноза (система плавно переходит на детерминированные шаблоны вывода).
3. **Конфиденциальность и безопасность:**
   - Данные пользователей строго изолированы на уровне запросов к БД;
   - В логах сервиса запрещено сохранять персональные данные клиентов, номера телефонов и платежные реквизиты;
   - SQL-инструмент в чате поддерживает исключительно оператор `SELECT` и принудительно ограничивает область видимости записями активного `snapshot_id`.
4. **Кроссплатформенность:** интерфейс корректно адаптируется под экраны мобильных устройств (iOS / Android) внутри WebView мессенджера MAX, а также поддерживает полноценный десктопный режим в браузерах.

## 12. Развертывание, Docker и Nginx

Проект разворачивается в сетевой архитектуре с Nginx в качестве единой точки входа:
- **Nginx (`nginx_xray.conf`):**
  - Терминация SSL (сертификаты Let's Encrypt);
  - Проксирование запросов к API: `location /api` $\to$ Gunicorn Django (`127.0.0.1:8000`);
  - Проксирование вебхука: `location /webhook/max` $\to$ Django (`127.0.0.1:8000`);
  - Проксирование панели администратора: `location /admin` $\to$ Django (`127.0.0.1:8000`);
  - Раздача статики и SPA фронтенда: `location /` $\to$ Vite / Nginx static.
- **Ограничения размера тела запроса:** `client_max_body_size 25m;` для поддержки загрузки объемных таблиц.

## 13. Критерии приёмки проекта

Система считается полностью принятой и готовой к промышленной эксплуатации, если:
1. Загрузка любого из 5 стандартных шаблонов приводит к корректному расчету 7 метрик без ручной настройки.
2. Стресс-тест со сленговыми названиями колонок (*«Баблос»*, *«Кто тащит»*, *«Время залива»*) успешно сопоставляется через AI-нормализатор.
3. Интерактивный AI-консультант корректно отвечает на сложные аналитические вопросы с использованием Tool Calling (`execute_sql_query`) и строит графики в ленте диалога (`render_chart`).
4. Формируются и успешно скачиваются брендированные файлы PDF-отчета и Excel-аудита.
5. История сканов сохраняет результаты, поддерживает мгновенное открытие любого снимка и удаление жестом свайпа.
6. В коде отсутствуют захардкоженные секреты, а токены мессенджера не передаются на сторону клиентского приложения.
